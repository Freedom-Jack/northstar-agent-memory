# Surface facts for the Northstar connectors, checked 2026-10-23

Corrects the facts of 2026-10-09 (N1-N19 in connector-strategy.md, W1-W24 in platform-and-devices.md) and the 2026-10-15 surfaces table (three-jobs-analysis.md). Nothing is built.
Needs: [1] capture both sides, [2] plain context at start and after compaction or clear, [3] a tool the model can call, [4] a note shown to the user outside the reply, [5] a check after each turn.
Status: "verified 10-23" = stated on that page on 2026-10-23 (documented, not tried on a machine). "unverified" = the vendor does not say, or only user reports say; test before relying on it. Source paths sit under the base URL in each heading.

## A. Claude Code: CLI and Desktop Code tab, Windows and Mac (base https://code.claude.com/docs/en/)
| ID | Fact | Status | Source |
|---|---|---|---|
| A1 | [1][2][5] 33 hook events fire the same in the terminal, IDE, Desktop app and cloud sessions; Mac and Windows differ in shell and failure rules (A9). Types: command, http, prompt, agent, mcp_tool. A SessionStart mcp_tool hook is skipped at launch (no MCP yet) but runs after /clear and compaction. | verified 10-23 | hooks |
| A2 | [2] SessionStart `source` is startup, resume, clear, compact or fork. additionalContext or plain stdout goes to the model, capped at 10,000 characters per string (no setting raises it). Hooks run in the background, but the first reply waits for them; if /clear or a conversation switch happens while they still run, their output is dropped. | verified 10-23 | hooks |
| A3 | [1][2] UserPromptSubmit gets the prompt text; additionalContext and plain stdout reach the model and leave no visible transcript entry; it can block; 30 s default timeout, and on timeout its context is discarded while the prompt still goes through. It also fires for /loop turns, background-subagent reports and cross-session messages. | verified 10-23 | hooks |
| A4 | [1][5] Stop gets last_assistant_message (the transcript file may lag, so use this) and stop_hook_active; a block or additionalContext continues the turn, at most 8 times in a row. PostCompact gets compact_summary; PreCompact can block. SessionEnd has a 1.5 s budget; reasons: clear, resume, logout, prompt_input_exit, other. | verified 10-23 | hooks |
| A5 | [4] systemMessage is "shown to the user" (no exception listed for SessionStart, UserPromptSubmit, Stop) but is discarded on PreCompact, PostCompact, SessionEnd, Setup, Notification, MessageDisplay. Async hooks (async, asyncRewake) send additionalContext and systemMessage to the model next turn and never show them to the user. terminalSequence can raise a terminal notification (Windows Terminal OSC 9 included) in interactive terminal sessions only. | verified 10-23 | hooks |
| A6 | [4] Desktop Code tab: the docs do not say whether systemMessage shows. User reports say it is dropped there and in the Remote Control mirror (UserPromptSubmit report closed "not planned" 2026-09-06; Pre/PostToolUse report; an open parity request #103739 on v2.1.304, title only seen). Plain-stdout context does work. | unverified (user reports, third-party mirror of anthropics/claude-code issues; test on the installed build) | https://claudeissues.com/issue/78266-userpromptsubmit-hook-systemmessage-does-not-render-in-the-desktop-app-or-vs-cod ; https://claudeissues.com/issue/77518-desktop-app-and-remote-control-sessions-never-render-hook-systemmessage-pretoolu |
| A7 | [1][3][4][5] Mods (new to our facts): plugin code that runs inside Claude Code in the CLI, Desktop Code tab and VS Code (not Desktop WSL sessions); on by default since 2.1.286/287 (Sep 30/Oct 1). A mod sees every prompt, reply and tool row (session.append) and the final answer (turn.complete, which can also return one line shown under the answer); it can add first-message context (prompt.context), register a model-callable tool (tool.register), and draw a pane or a band above the prompt, which the Desktop app renders. Limits: 10 s per hook; Anthropic can switch installed mods off remotely; managed settings can block them. | verified 10-23 | plugins/mods/overview, reference, events, api, interface, admin |
| A8 | [4] In the Desktop app a mod's ui.notify returns "no-surface" (it needs a terminal). Whether toast, status line, log line or the turn.complete line render in Desktop is not stated; only panes, the band and message redraws are listed for Desktop. The MessageDisplay hook can replace the text shown on screen (display only; transcript and model keep the original); its Desktop support is not stated. | unverified (toast, status, log, turn line, MessageDisplay) | plugins/mods/api, reference; hooks |
| A9 | Windows hooks: shell form runs in Git Bash, else PowerShell (`shell: powershell` allowed); exec form needs a real .exe. Since 2026-10-15 (Desktop v2.42304.0) a failed PreToolUse or PermissionRequest hook on Windows without Git for Windows blocks the tool unless shell, args or onFailure is set. PowerShell hooks did not block on exit code 2 until 2.1.309 (10-22). CLAUDE_ENV_FILE is not available to PowerShell hooks. | verified 10-23 | hooks; https://claude.com/docs/cowork/changelog ; changelog |
| A10 | /goal wraps a session-scoped prompt-based Stop hook. After each turn a small fast model (Haiku class) reads the condition plus the conversation so far, with no tools, and answers met, not met (reason goes back to Claude) or impossible. Works in the Desktop app, `-p` and Remote Control; condition up to 4,000 characters; cleared by /clear; restored on resume; unavailable if hooks are disabled. | verified 10-23 | goal |
| A11 | [3] Plugins bundle skills, agents, hooks, a mods module and MCP servers; installed with /plugin or the Desktop plugin browser; account plugins from claude.ai sync into Claude Code; none in Desktop WSL sessions. The Desktop Code tab also loads MCP servers from claude_desktop_config.json. | verified 10-23 | plugins/overview; desktop; https://claude.com/docs/plugins/platform-support |
| A12 | [1] Transcripts: `~/.claude/projects/<project>/<session>.jsonl` (`%USERPROFILE%\.claude` on Windows). cleanupPeriodDays defaults to 30. A session started or last continued in Claude Desktop or Cowork keeps its transcript at any age (2.1.248+) unless managed settings set the period, HIPAA applies, or desktopSessionCleanupPeriodDays is set. The page names only the transcript for that exemption; tool-results and file-history (newest 100 checkpoints) follow the 30-day sweep. Since 2.1.300 transcripts also hold each request's system prompt and tools. | verified 10-23 | claude-directory; settings-reference; changelog |
| A13 | Remote Control: Pro, Max, Team, Enterprise (not API keys, Bedrock or gateways). The session runs on your computer with its files, MCP servers and config, so the computer must stay on. Start with `claude remote-control`, `claude --remote-control` or /remote-control (also in Desktop and VS Code); remoteControlAtStartup makes it automatic. Mod hooks run there and mod drawings appear only there. | verified 10-23; settings hooks firing for phone-typed prompts only implied by changelog fixes: unverified | remote-control; plugins/mods/overview |

## B. Codex: CLI, IDE extension, ChatGPT desktop app (base https://learn.chatgpt.com/docs/)
| ID | Fact | Status | Source |
|---|---|---|---|
| B1 | [1][2][5] Hook events: SessionStart, UserPromptSubmit, Stop, PreCompact, PostCompact, SessionEnd, Interrupt, tool and subagent events. Generally available since 2026-05-14, on by default. In hooks.json, `[hooks]` in config.toml, or bundled in plugins (env PLUGIN_ROOT and CLAUDE_PLUGIN_ROOT). Each non-managed hook must be reviewed and trusted; trust is tied to its hash, so an edited hook is skipped until re-trusted. command and mcp_tool handlers run; prompt and agent handlers are skipped. | verified 10-23 | hooks; changelog |

| B3 | [1][5] UserPromptSubmit gets the prompt (plain stdout or additionalContext is context; can block). Stop gets last_assistant_message, needs JSON on stdout, and a block creates a new continuation prompt. PostCompact has trigger only, no summary. SessionEnd: reason always `other`, 1 s default (max 3 s), runs on close, archive or 30 min idle. A `notify` program can also run on agent-turn-complete. | verified 10-23 | hooks; config-file/config-advanced |
| B4 | [4] systemMessage is "surfaced as a warning in the UI or event stream" on SessionStart, compaction, UserPromptSubmit, Stop and tool events. Async hooks (async: true, 8 at a time) surface it as a warning too, unlike Claude Code. statusMessage shows text while a hook runs. Which screen shows it in the Windows app is not stated. | verified (Windows app display: unverified) | hooks |
| B5 | Windows: per-hook `commandWindows` override. The desktop app on Windows runs the agent natively in PowerShell (or WSL2); state lives in `%USERPROFILE%\.codex`; a WSL CLI keeps its own Linux home unless CODEX_HOME is set. | verified 10-23 | hooks; windows/windows-app |
| B6 | Hooks run in local Codex and local-only Work threads. With Local computer access with Work Cloud (new tasks after sync is enabled), command and plugin hooks are not supported (admin MCP hooks only). IDE extension: hooks not stated; it has no plugins. | verified; IDE hooks unverified | hooks; plugins; extend/mcp |
| B7 | [2] AGENTS.md: `~/.codex/AGENTS.md` (or AGENTS.override.md), then each directory from project root to cwd, one file each, joined in order; 32 KiB cap (project_doc_max_bytes); built once per session. | verified 10-23 | agent-configuration/agents-md |
| B8 | [3] MCP: STDIO and Streamable HTTP servers; one config (`~/.codex/config.toml`, project `.codex/config.toml` if trusted) shared by CLI, IDE and desktop app; Codex reads the server `instructions` (first 512 characters matter); per-tool approval modes auto, prompt, writes, approve; hooks can call MCP tools. | verified 10-23 | extend/mcp; hooks |
| B9 | [1] Session files: docs name CODEX_HOME (default `~/.codex`), history.jsonl, and the hook field transcript_path, "not a stable interface" that "may change". | B10 | Memory: local Codex memories are off by default (Settings > Personalization, or `[features] memories = true`); files in `~/.codex/memories/`; /memories per chat; memories.disable_on_external_context keeps chats that used MCP or web out of memory generation. ChatGPT Chat and Work use ChatGPT memory instead. | verified 10-23 | customization/memories |
| B11 | The ChatGPT iOS "Codex" tab works with ChatGPT or Codex chats on a connected Mac or Windows host running the desktop app (awake, online, same account); MCP servers, skills and plugins come from the host. Goal mode (/goal) left experimental on 2026-05-21 and is in app, IDE and CLI. | verified 10-23 | remote-connections; mobile; changelog |
